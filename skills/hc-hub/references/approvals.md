# approvals（承認待ちへの対応）

worker が承認待ちで止まり、自律的な進行が途切れることを最も避ける。hub は次の範囲で自分で答え、範囲の外は人に上げる。

## hc 公式の既定を、この範囲で上書きする

hc の手引き（`hc --skill`）は「`blocked` は人に尋ねよ、`--force` で迂回するな」と言う。hc-hub は、この節の表の範囲に限り、これを上書きする。範囲の中では hub が画面を読んで答える。範囲の外では、手引きどおり人に尋ねる。

## 何を誰が答えるか

roster の `approval: auto | manual` で中段の行が切り替わる。値が `auto`・`manual` 以外、またはどこにも書かれていなければ、roster の検証でエラーになる。暗黙の既定は無い。

| 入力待ちの種類 | `auto` | `manual` |
|---|---|---|
| plan mode の承認、フォルダの信頼の確認、選択肢のメニュー、続行の確認 | hub が答える | hub が答える |
| 通常の権限確認（分類器でも hook でもない「この Bash を実行してよいか」など） | hub が画面を読んで答える | 人に上げる |
| 分類器・hook が止めた、人の承認が要るルールに当たった | 人に上げる | 人に上げる |

この設定は hc-hub の層のもの。エージェント自身の権限モード（例: Claude Code の `--permission-mode`）とは独立で、後者は `command` の引数で選ぶ。判断がつかない場合は人に上げる。

## hub が答えるとき

1. `hc-hub guard --op read <t>` を打ち、`hc read <t>` で画面を読む。読まずに答えない
2. 画面が表の上段・中段のどれかを確かめる。分類器・hook・ルールの停止なら「人に上げる」へ進む
3. `hc keys <t> …` か `hc send --force <t> …` で答える（前に、それぞれ `hc-hub guard --op keys <t>`・`hc-hub guard --op send <t>`）

`blocked` の宛先への通常の `hc send` は、`--force` が無いと exit 9 で拒否される。拒否は「画面を読んでから答えよ」の合図で、読んだあとに `hc send --force` か `hc keys` で答える。キーの形はエージェントごとに違う（[agents.md](agents.md)）。

答えたあとは `hc read` でもう一度画面を見て、通ったことを確かめる。

### 設定に残る選択肢は選ばない

「今後は確認しない」「常に許可する」のような、設定ファイルや許可リストに残る選択肢は、`auto` でも選ばない。その回だけを許可する選択肢を選ぶ。その回だけの選択肢が無ければ、人に上げる。

### plan mode

計画が依頼の範囲から外れていないかを、依頼ファイル（`hc-hub.brief` ラベル）または最初の依頼と照らして確かめてから承認する。外れていれば承認せず、外れた点を worker に `hc send` で返す。

## 人に上げる

次の 3 つに当たったら、`approval` に関係なく答えない。

1. エージェントの分類器が止めた
2. hook が止めた
3. 人の承認が要るルールに当たった。ルールの中身はプロジェクト側の rules ファイルにある。この skill は「書かれていれば上げる」という枠だけを持つ

手順は次のとおり。

1. 止めた表示を逐語で控える（要約や言い換えにしない）
2. `hc-hub guard --op label <t>` を打ってから、待っている worker に `hc label <t> hc-hub.needs-human=1` を付ける
3. 自分の画面（人が読む場所）に、止めた表示の逐語と、何を決めてほしいかを書く（[escalation.md](escalation.md)）
4. 人の答えを受けたら、その答えを worker に伝え、`hc-hub.needs-human=1` を外す（外す前にも `hc-hub guard --op label <t>`）

値を固定の `1` にするのは、`hc ls --label` が完全一致でしか絞れず、複数の worker が同時に待つこともあるため。人は `hc ls --label hc-hub.needs-human=1` で、どの worker が人を待っているかを全レーン分一覧できる（行の `where` でレーンの場所もわかる）。

人に上げている間も、他の worker は止めない。

## hub 自身も表面を変えて通さない

分類器や hook に拒否された操作を、hub 自身が形を変えて通そうとしない。コマンドの書き方を変える、分割する、別の経路で同じ効果を得る、worker に代わりにやらせる、はすべてこれに当たる。拒否されたら、そこで人に上げる。

## 気づけない止まり方

- 起動直後に信頼の確認ダイアログで止まると、状態が `null` のままで `blocked` の通知も来ず、`hc wait` も返らない（実測）。`hc wait` の返りを待たず、起動後に状態が `null` のままなら `hc read` で画面を確かめる
- 状態を報告しないエージェントでは、承認待ちに気づけない。起動時の検査で止まり、人に知らせる（[agents.md](agents.md)）
