# 裁定の境界と決断の要求

hub がどこまで裁き、どこから人間へ上げるかの線引きと、決断の要求の出し方。

## 裁定の境界 — どこまで hub が裁き、どこから人間へ上げるか

**下り（人間 → hub → worker）だけでなく、上り（hub → 人間）の線を先に引く。**
線が無いと hub は 2 通りに外れる — **裁いてはいけないものを裁く**か、**裁けるものを上げて人間を詰まらせる**か。

| hub が裁く | 人間へ上げる |
|---|---|
| 作業の分割・境界 / 作業順と並行化 | **正典（spec・ADR・設計文書）が矛盾している、または記述が無い設計判断** |
| review の依頼先と観点 / merge の時機（※下記） | 費用が出る操作 / 破壊的・不可逆操作 |
| 実装の置き場（既存規約の適用） | 依存の追加 / スコープの変更 |
| worker の報告の受理 | |

※ **merge の「時機を提案する」のは hub、merge 実行の承認はプロジェクト規律次第**（多くでは人間の承認が要る — 例えば merge gate の条件を C 層 `rules` file で定める）。merge 実行そのものは不可逆に近い操作なので、規律が未定義なら右列として人間へ上げる。

**正典が矛盾しているときに自分の原理で解こうとしない。** これは「裁いてはいけないものを裁く」の典型である。

**上げ方**:

- 🔴 **N 択に整形しない。「どうなっているか」を書いてから推奨を 1 つ出す。** 受け手は列挙の中から答えるので、列挙の外にある答えが消える。実例: 2 択で上がってきた問いの正解は列挙の外（その観測設計自体をやめる）だった。
- **影響範囲を書く。** 「実装は止まりません」なのか「これが決まらないと進めません」なのかで、人間の優先度が変わる。
- **急がないなら「急ぎません」と明記する。** そう書いたことで、裁定を待ちながら実装を止めずに済んだ実例がある。
- **裁定が出たら逐語 + 裁定日で全 worker へ配り、正典への転記まで確認する。**

## 🔴 hub が裁くのは不変条件であって手段ではない

**上の表は話題で切っている。切るべき軸がもう 1 本ある — 層である。**
hub は「**何が真なら先へ進んでよいか**」を裁き、「**どう実現するか**」は worker が決める。

**実測**: hub の**手段の裁定 5 件は 5 件とも worker の実測で訂正され、不変条件の裁定 3 件は 0 件覆った**。
判断力の差ではない — **手段の当否は走らせないと出ず、hub は走らせる側に居ない**。
害は誤りでなく**経路**にある: 手段を hub が裁くと訂正が毎回数往復（測る→報告→改訂→配る）を通り、**人間から見える設計がそのたび動く**。

- **手段を書くのは「候補」としてだけ。**「⚠ 未検証・差し戻し歓迎」を添える。**候補が裁定の顔をすると worker は検証をやめる**（[adjudication.md](adjudication.md)「hub 自身の出力を疑う」の裏面）。
- **worker が手段を上げてきたら、裁定でなく不変条件を返す** —「どちらが良いか」ではなく「**何を満たせばあなたが選んでよいか**」。
- ⚠ **「hub は黙る」ではない。** 横断の検査（「その結論は今日すでに否定した形ではないか」）は hub にしか出せない。

## 🔴 決断の要求は、前提が動き終わってから出す

**実測**: hub が実行の可否を人間へ上げ、**回答待ちの往復のあいだに目的である設計が 5 回変わった**。**そのたび「出し切りました」と書き、4 回とも確定していなかった。**

- **前提に「worker がこれから測るもの」が 1 つでも残っていれば、その問いは出さない。** 測り終えてから 1 通で出す。
- **確定していないものを確定の語で書かない。**「出し切りました」「以上です」は次便の可能性が無いときだけ。代わりに「**暫定 — X を測るまで動きます**」。
- ⚠ **分けるのは「報告」と「決断の要求」。** 進捗は動いてよく、決断待ちは動いてはいけない。
- ⚠ **「方針が変わること自体が悪い」と読まない。** 直すべきは頻度でなく**人間の決断待ちを横切る経路**である。

**判断を出す前に 2 つを問う**（実害からの追加 — hub が本節を 3 度踏み、いずれも自分では気づかず人間か worker が捕まえた）:

- **「その判断はそもそも要るか（正典が既に答えていないか）」**
- **「worker と推奨が一致しているなら、それは判断の要求ではない」**

⛔ **逆方向にも振れない。** 人間が「継続可能」と伝えてきたことへ「急ぐ理由は無い」と hub が優先度まで裁定した例がある。**「決断の要求を減らす」を「人間の領域まで自分で決める」へ広げない** — 急ぐ理由の有無は人間が決める。
