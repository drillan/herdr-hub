# hc-hub 実装計画

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Herdr 2（herdr-core `hc`）の上で、レーンごとの hub が worker を自律的に起動・監視・停止する配布 skill `hc-hub` を作る。

**Architecture:** `skills/hc-hub/` に SKILL.md（骨子と索引）と references を置く。静的に決まる規則（roster の検証と解決、台帳の追記と読み取り、操作前ガード、§0 の前提検査）は、runbook の文章ではなく同梱の Python CLI `scripts/hc-hub` に実装し、hub はそれを呼ぶ。hc の構文の正典はインストール済みのバイナリで、手引きの本文は写さない。

**Tech Stack:** Markdown（skill 文書）、YAML（roster）、JSON Lines（台帳）、Python 3.13 の単一エントリ CLI（PEP 723、`uv run --script` で実行、依存は PyYAML のみ）、pytest・ruff・mypy（開発時のみ）

**Spec:** `docs/superpowers/specs/2026-10-31-hc-hub-design.md`

## Global Constraints

- 本文は日本語（コマンド・識別子・固有名詞は原語）。`herdr-hub`・`herdr-session` の中身は変えない
- この repo の追跡ファイル・コミットに、運用元の業務プロジェクトの名前を出さない
- 「フォールバック」という語を使わない。エラー時に既定値・空値で続行しない（例外を送出し、CLI は非 0 で終わる）
- skill 名 `hc-hub`、置き場所 `skills/hc-hub/`、roster の既定パス `./.hc-hub.yml`
- ラベルのキー: `hc-hub.lane`・`hc-hub.role`・`hc-hub.brief`・`hc-hub.needs-human=1`（Task 0 の実測でキーに `-`・`.` が使えないと分かったら、全タスクのキー名を同じ規則で置き換える）
- 解決の順序: `defaults` → `lanes.<名>` → preset → 個別（後が優先）。`rules` だけは全段の union
- `approval` は既定値なし（解決できなければエラー）。`placement` の既定は `tab`。`handoff_at` の既定は `0.8`（既存 `herdr-hub` と同じ）
- 名前・レーン名は hc の制約 `^[a-z0-9_-]{1,32}$` に従う
- 最初の版は同じマシン限定。`on:` などの別マシンの指定はエラー
- Python: `uv run` を使い `python3` を直接使わない。コミット前に `uv run ruff check --fix . && uv run ruff format . && uv run mypy .` を通す

## Review Focus

1. **roster の段の取り違え**: preset に書いた `approval` がレーンの値に負ける、または `rules` が上書きされて消える。→ Task 2 の `test_resolve_order_*` と `test_rules_union_keeps_all_stages`
2. **台帳への同時追記**: 2 つのレーンの hub が同時に追記して行が混ざる、または壊れた 1 行が黙って読み飛ばされる。→ Task 3 の `test_append_is_single_write` と `test_corrupt_line_raises_with_line_number`
3. **ラベルの無い宛先・他レーンの worker への操作**: `send` 以外の操作（`label`・`put`・`kill`）が他レーンの hub に通ってしまう。、または hub 自身にラベルが無いまま操作が通る。→ Task 4 の `test_cross_lane_hub_only_send` と `test_self_without_lane_or_role_refused`
4. **旧 roster の持ち込み**: `kind`・`transport`・`placement: pane` を書いた旧形式の roster が、黙って一部を無視されて動く。→ Task 2 の `test_removed_keys_raise_with_replacement`
5. **ウィンドウの外の hub と `placement: tab`**: hub に `herdr.space` が無いのに tab を要求され、黙って hidden で起動する。→ Task 4 の `test_spawn_argv_tab_without_space_refuses`（起動引数を CLI が組み立てるので、文書の手順を飛ばしても黙って hidden にはならない）
