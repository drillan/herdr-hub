# briefing（worker へ渡す雛形）

worker が受け取る唯一の作法書は briefing である。worker はこの skill を読まない前提で、**動くのに必要な全てをここに書く**。

## 7 ブロック

この順で書く:

1. **宛先 guard** — 「このメッセージは agent `<name>` 宛です。あなたの名前が違うなら着手せず hub へ返信してください」
2. **役割と一元化** — あなたの roster 上の役割 / 指示は hub からのみ / 人間への直接の質問はしない。roster に `role_file` が指定されている agent には、hub がそのファイル内容を役割ブロックへそのまま注入する
3. **最初の一手** — 何を・どこから始めるか
4. **その担当が最初に踏む既知の罠** — 前任の失敗・申し送りをここへ集約。**必ず埋める**（最も効くブロック。空なら同じ穴を 2 度踏む）
5. **作法** — 下記「worker の作法」
6. **境界** — やってよいこと・止まる条件（許可が要る操作、スコープ外）
7. **進め方** — 報告の粒度・区切り・終了条件

## worker の作法（⑤ に含めるもの）

- **あなたの名前は `<name>`。** 返信・報告は `herdr agent prompt hub "..."`（または Claude なら SendMessage で `hub` 宛）で **hub へ**
- roster 上の他 agent の名前と役割（誰に何を直送してよいかの判断材料）
- **進捗・判断・罠は `/tmp/herdr-hub/<name>.log` へ随時追記する**（交代時の handoff はこれへの参照になる → [context-and-handover.md](context-and-handover.md)）
- **他 agent を `herdr agent wait` 等で監視しない。** 待つべきものがあるときは「何を待っているか」を 1 行で hub へ投げてターンを終える
- **新しい作業（issue・別タスク化）を自分で発行しない。** 「候補」として hub へ上げる
- **承認 UI で止まったときはそのまま待つ** — hub 側には `agent_blocked` として見える
- 判断・裁定が必要に見えたら hub へ上げる。自分の権限を越える決定をしない

## 「裁定」の明記

hub が自分の推奨を worker へ送るときは **「これは私の裁定であり人間の決定ではない」と本文に明記する**。書かないと受け手には hub の推奨と人間の決定が同じ形で届く。逆に人間の決定を転送するときは**決定文を逐語で添える** — 「承認済みの認識です」は転送ではない。

## 交代時の分担

交代では briefing を 2 人で書く（手順は [context-and-handover.md](context-and-handover.md)）:

| 書き手 | ブロック |
|---|---|
| **hub** | 宛先 guard / 役割と一元化 / 作法 / 境界 / 進め方（roster 全体の文脈は hub にしかない） |
| **前任** | 現在の状態 / 最初の一手 / 既知の罠（落とした本人が最も詳しく、hub 中継は情報を落とす） |

交代時はブロック 3（最初の一手）の直前に「**現在の状態**」を挿入した 8 ブロック版を使う。

前任が送る内容を hub は検査してよいが、**書き換えて自分の文にしない** — 中継の圧縮で本体が落ちる型になる。
