# messaging（送受信の作法）

送信は transport（[transports.md](transports.md)）を選び、ここに書くのは全経路共通の作法。

## 送信

- **非同期が既定。** `--wait`（herdr）やそれ相当の待機は「送って即答が要る」同期照会だけに使う。普通の指示・裁定は投げたら送信側のターンを終える
- **送信前 guard**: 宛先名が live に解決することを確認してから送る

  ```bash
  herdr agent list        # herdr / codex-queue 宛先
  # Claude 宛は ListAgents
  ```

  「宛先が実在するか」の確認だけでは足りない — 実在確認を通って別人に届く。roster の名前と live の名前を照合する
- **本文中で他 agent を指すときも名前を併記する。** guard が守るのは宛先だけで、本文内の言及は守らない

## 返信

- worker → hub は `herdr agent prompt hub "..."`（または SendMessage で `hub` 宛）
- worker がこの経路を知るのは briefing だけ — **briefing に「あなたの名前」「roster」「返信は hub 宛」を必ず書く**（[briefing.md](briefing.md)）
- 承認済みの成果物・測定値は worker → worker で直送してよい。**判断・裁定・新規の指摘は hub 経由を維持する**

## 待機・監視

- 🔴 **`herdr agent wait` で他者を監視する指示を出さない。** ターンを終えた agent は何もしないし、wait を回す agent は自分の文脈を監視に浪費する
- Claude 間では SendMessage の `notify_when_idle` を使う。それ以外は「終わったらこちらへ報告せよ」を briefing/指示に書く — **起こすのは受け手**
- 🔴 **「追います」「完了まで待ちます」を書かせない**（worker にも hub 自身にも）。代わりに書くのは「いま何を区切ったか」と「次に誰が動くか」だけ

## 中継は情報を落とす

hub の中継は圧縮の工程であり、受け手は「来なかったもの」を観測できない。型ごとの処方:

| 型 | 処方 |
|---|---|
| 列挙の一部が落ちる | 指示に「N 件のうち M」と集合を再掲する |
| 参照だけ渡して本体が落ちる | 本文を同梱するか、「本人から直送させる」と明記する |
| 数えずに数を書く | 行ごとの内訳を書いてから合計する |
| 多義語を渡す | 状態は「生存 / 停止中 / 終了」等の限定語彙で書く |

- **送信のたびに通し番号と総通数を添えさせる**（(a)(b)(c)… +「本便まで N 通」）。未達 1 通はこれだけで検出できる
- **訂正・追補は「前便が生きているか」を 1 行目に書かせる**
- **worker に「私が渡した数値・区分は取り直せ」を毎回書く**

## 往復を減らす

- **ack を求めない。**「待機します」は決定を運ばない。次の指示まで待機が既定
- **訂正は次便に相乗りさせる。**単独で出すのは前便の結論が覆るときだけ
- **指摘は 1 便に合流させる。**指摘の源は非同期に届くので、届いた順に流すと受け手は同じ対象を何度も直す。blocker（そのまま進むと後続が無駄になるもの）だけ例外
- **照会には終了条件を始める前に書く。**巡回中に作った終了条件は gate の自己裁定。往復が伸びたら受け手の成果物ではなく**自分が渡した前提を疑う**

## 着地

- 担当分が着地し次の割り当てが無いなら、その agent へは何も送らない。「終了です」通知も送らない（待機は既定状態）
- 着地報告への返信・受領確認・評価の擦り合わせはしない
- **例外は 1 つ**: 走行中の review・照会を止める「停止」の 1 行。merge/完了を走行中の側は観測できないので、送らないと止まらない
